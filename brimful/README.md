# Brimful

Savings jars and savings challenges you can watch fill up. A static, local-first web app (PWA): no accounts,
no build step, no analytics. Live at https://brimful.vercel.app

## How it's put together
| Part | Where | Notes |
|---|---|---|
| Landing page | `index.html`, `assets/css/landing.css`, `assets/js/landing.js` | Scroll-driven WebGL jar (three.js), GSAP ScrollTrigger, Lenis |
| App | `app/index.html`, `assets/js/app.js`, `views.js`, `share.js` | Hash routes: jars, jar, challenges, split, settings, unlock |
| Logic (tested) | `assets/js/lib/money.js`, `challenges.js`, `store.js` | Pure functions; amounts are integers in minor units |
| 3D jar | `assets/js/lib/jar3d.js` | Decorative; falls back to an SVG jar without WebGL |
| Legal pages | `legal/*.html` | Generated by `python3 tools/build-legal.py` (edit the text there) |
| Payments | QuoteRevive backend: `quoterevive/src/app/api/store/` | Orders reviewed at quoterevivepro.vercel.app/app/admin/payments |

User data lives in `localStorage["brimful:v1"]` on the user's device. The only network calls are to the payments
API when buying or restoring Plus (`assets/js/lib/api.js`).

## Run, test, deploy
- Run locally: `python3 -m http.server 4173` then open http://localhost:4173/app/
- Tests: `npm test` (Node 22+, no dependencies)
- Images: `node tools/make-images.cjs` regenerates screenshots and icons (needs Playwright)
- Deploy: push to `main`; the Vercel project `brimful` (root directory `brimful`) deploys automatically

## Changing things
- **Price:** set `STORE_BRIMFUL_PRICE_ETB` on the *quoterevive* Vercel project (default 500), redeploy it, and update the "500" in `index.html`.
- **Payment details:** `quoterevive/src/lib/offer.ts` (`LOCAL_PAY`) and `assets/img/pay-telebirr.jpg`.
- **Free limits / styles:** `FREE_LIMITS`, `FREE_STYLES` in `assets/js/lib/store.js`.
- **Colours and fonts:** variables at the top of `assets/css/base.css`.
- **After changing any app file:** bump `VERSION` in `sw.js` so installed copies update.
